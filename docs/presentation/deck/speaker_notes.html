AIA_06 → Практика разработки ИИ агентов ⭐.

AIA_07 → Сбор метрик и деплой ИИ агентов.
Метрика квиза — взвешенный токенный F1 из седьмого ноутбука (ADR-009). Command(resume) держит диалог в MCP, деплой — FastAPI REST+SSE (PSA-T2).

AIA_08 → Архитектура современных агентных harnesses (PDF).

Слайд 9 · Hook
Доклад начинается с вопроса, а не с темы.
Начну с простого вопроса. Разработке учат показом кода: ревью, парное программирование, примеры. А Spec-Driven Development учат чтением документации. Спека — центр методологии, но тренера у неё нет. Мой проект закрывает именно этот пробел.
Слайд 10 · Cover
Три цифры — и обещание доказательств.
Это SDD Trainer — ИИ-тренер по спекам. Три цифры на слайде: двести сорок девять тестов, покрытие почти семьдесят девять процентов при гейте в сорок, и семь MCP-инструментов — stdio плюс Streamable HTTP. Все цифры — из живых прогонов, доказательства будут дальше.
Слайд 11 · Проблема
Три боли обучения по докам.
SDD — это когда спецификация источник истины: план, дельты, критерии приёмки. Учить его по документации больно: курс не знает твой уровень, не даёт обратной связи и не проверяет понимание. Отсюда требование к решению: калибровка, адаптация, проверка.
Слайд 12 · Решение
Ядро — граф; решения без парсинга текста.
Ядро тренера — LangGraph-граф. Сначала калибровочный вопрос, потом развилка. Четыре маршрута: уверенное владение ведёт сразу на квиз, частичное — на урок по пробелам, новая тема — на полный урок, низкая уверенность — в уточняющий цикл. Важно: решение принимает модель через structured output, никакого парсинга свободного текста.
Слайд 13 · Архитектура
Вся система на одном слайде — каждый блок несёт номер критерия.
Теперь система целиком: у неё три входа — консоль, FastAPI REST+SSE и любой MCP-клиент — и все ведут к одному и тому же ядру. FastAPI-процесс даёт REST-эндпоинты и SSE-стрим, и он же монтирует MCP на слэш-mcp — один процесс, второй шов (ADR-001). MCP-хост ходит через Streamable HTTP, stdio остаётся fallback. Между ними тонкий транспорт: FastMCP-сервер из семи stateless-инструментов. В ядре — граф, инструменты поиска и анализа, LLM-менеджер со structured output. Всё состояние — в чекпоинте, внешние вызовы — cloud.ru и Tavily. Кружки на блоках — номера критериев курса: архитектура закрывает все шесть.
Слайд 14 · Демо
Реальный сеанс, дословно.
Вот реальный сеанс из моего проверочного прогона. Ученик отвечает слабо — уровень partial, уверенность ноль восемь пять. Граф выбрал урок, потом квиз из пяти вопросов. Итог — единица, зачёт, прогресс записан. Каждое слово на слайде — дословная цитата транскрипта.
Слайд 15 · Критерии 1–5
Каждый критерий — конкретным файлом.
Пробегусь по критериям курса. GigaChat через cloud.ru — менеджер с fallback-моделью. Граф — StateGraph с условными рёбрами. Два инструмента: живой поиск по документации и анализ репозитория. Память — SqliteSaver с тредом ученика. Роутинг — четыре маршрута вместо требуемых трёх.
Слайд 16 · Критерий 6
MCP — не обёртка, а новый шов.
Шестой критерий — MCP. Сервер на FastMCP лежит поверх того же графа: один вызов инструмента — один шаг графа до следующего interrupt. Критерий закрыт буквально: FastAPI-процесс со слэш-mcp по ADR-001 — REST, SSE и MCP в одном процессе, stdio — fallback. Инструменты stateless: имя ученика — единственный ключ, чекпоинт — единственное состояние. Стандартный вывод чист, это проверяет реальный stdio-сабпроцесс в интеграционном тесте.
Слайд 17 · Антифейк
Главный кадр: kill и resurrect.
Самое сильное доказательство. Я довожу сеанс до середины квиза и убиваю сервер — жёстко, вместе с клиентом. Запускаю новый процесс, тот же ученик. Граф отвечает resumed равно true и возвращает тот самый третий вопрос. Доквиз — и зачёт. Это дословные строки логов, никакой постановки.
Слайд 18 · Рекурсия
Проект сам — кейс собственной методологии.
Вишенка: тренер учит SDD и при этом построен по SDD. Предложение, спека с дельтами, тикеты, TDD, независимая проверка, архивация. Четыре change, четырнадцать закрытых тикетов, валидация четыре из четырёх. Проверяющие могут открыть openspec-папку и увидеть весь процесс в коммитах.
Слайд 19 · Итоги
Фазы закрыты, дальше — сдача.
Итого: обе фазы закрыты, плюс FastAPI REST+SSE с MCP-монтом в том же процессе и get_student_history. Тесты зелёные — двести сорок девять, покрытие почти семьдесят девять процентов. Дальше — скринкаст до десяти минут по готовому сценарию и сдача тринадцатого ноября. Код открыт, приглашаю проверить. Спасибо!
Слайд 20 · Приложение A1 · Карта курса
Восемь ноутбуков — восемь компонентов.
Слайд отвечает на вопрос «а причём тут курс». Каждый ноутбук превратился в конкретный компонент тренажёра — от API-клиента из первого до F1 из седьмого. Главный шаблон — шестой ноутбук, роутинг-агент. Честная оговорка про три расхождения плана и реализации: ReAct заменили детерминированным роутингом ради воспроизводимости вердиктов, GigaSearch не понадобился, а REST+SSE реализованы — MCP смонтирован в тот же процесс, не замена, а второй шов — паттерн interrupt/Command из седьмого ноутбука тот же.
Слайд 21 · Приложение A10 · Три наследования
Паттерн из ноутбука — строка в коде.
Три истории глубже. Роутинг-агент из практики шестого ноутбука — скелет всего тренажёра: те же узлы оценки и маршрутизации. Упражнение с чекпоинтером из четвёртого стало фичей рестарта — тот самый кадр скринкаста. А паттерн interrupt/Command из седьмого — это буквально строка двести девяносто шесть сервера: каждое сообщение ученика продолжает прерванный граф. Итог: курс не остался теорией.
Слайд 22 · Приложение A11 · Бюджет агента
Мета-цифра: проект разработан ИИ-агентом.
Мета-цифра доклада: весь проект разработан ИИ-агентом — около трёх целых трёх десятых миллиона токенов — по тарифу cloud.ru это примерно девятьсот рублей — по семнадцати сессиям. Самый дорогой кусок — Фаза один, где контент писался с нуля. Ревью и координация — около двадцати процентов бюджета, это цена качества: независимая проверка кода и плана плюс работа основной сессии. API предоставлен в рамках курса — в логах не тарифицируется.
