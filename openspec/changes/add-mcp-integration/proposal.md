# Proposal: Add MCP Integration (Phase 2)

**Phase:** 2 — MCP-прототип (вытащен вперёд из фазы 3 по итогам консультации №1)
**Effort:** ~2 дня (4–5 ноября)
**Источники:** консультация №1 (03.11.2026); GitHub Issue #1; ADR-001, ADR-008; proposal add-console-trainer (имя change-а зарезервировано там)

## Problem

Консультация №1 (03.11): преподаватель хочет видеть **работающий прототип** — код вторичен. Консольный тренер (Фаза 1) работает end-to-end, но показать его можно только в терминале: ни один внешний агент-клиент не может использовать тренера как инструмент.

## Solution

MCP-сервер поверх существующего графа — без переписывания ядра:

- FastMCP (официальный python SDK, `mcp==1.27.1` уже запинен в скелете Фазы 0), транспорт stdio
- Инструменты сессии = пошаговое возобновление чекпоинченного графа (thread_id = student, ADR-008): каждый вызов доводит граф до следующего interrupt и возвращает его payload
- Прямой доступ к tools тренера (`analyze_student_repo`, `search_sdd_docs`) и прогрессу (training-state)
- Демо: SDK MCP-клиент скрипт — автодемо для скринкаста; конфиг для подключения к реальным MCP-хостам

Любой MCP-клиент (Claude Desktop, Cline, OpenClaw) становится учеником тренера — это и есть «работающий прототип» в смысле преподавателя.

## Out of scope

- FastAPI (`add-fastapi-service` — отдельный change; решение принимается после MCP-прототипа)
- socratic-режим, HITL-квизы, остальные 5 доменов, spaced repetition
